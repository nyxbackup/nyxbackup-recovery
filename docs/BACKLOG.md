## Keep reading what the main app writes (refresh the conformance fixture)

`crates/bkp-restore/tests/fixtures/format-v2/` was generated by the main
app's 1.0.0-era `gen_recovery_fixture`, which wrote packs flat
(`packs/<pack>.pack`).  Real backups put them in `packs/<machine>/<set>/`
(REQ-060), so the committed fixture never tested finding packs in the real
layout.  The main app's generator writes the real layout since 2026-11-07
(nyxbackup-backup `gen_recovery_fixture`, after `d0105213`).

Checked 2026-11-07, outside this repo: the v1.0.0 `format_conformance` test
passes (4/4) on fixtures freshly written by Nyx Backup 1.0.7 code, in both
the flat and the real layout - manifest, snapshot index and a byte-for-byte
restore.  So 1.0.7 does not break recovery.

To do:
- Regenerate the fixture from the main repo
  (`cargo run -p bkp-engine --example gen_recovery_fixture -- <this repo>/crates/bkp-restore/tests/fixtures/format-v2`)
  and commit it, so this repo's own test covers the real layout.
- Before every Nyx Backup release that changes the manifest, snapshot index,
  pack layout or `SetRecord`, regenerate and re-run `format_conformance`
  (and the `--foreign` variant).  This tool keeps its own copy of the pack
  path rules, with nothing else keeping the two in step.
